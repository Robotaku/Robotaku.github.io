# 追跡ゲーム (chase-game)

スコットランドヤード風の追跡ゲームです。1台の端末を交代で使って遊びます。人間は2人以上、そこに好きな数のBotを加えられます。

## 概要

- 逃走者1人と追跡者1人以上で遊びます。逃走者は地図上の駅を移動し、その位置は追跡者から隠されます。
- 追跡者は、逃走者が使った移動手段とわずかな位置公開を手がかりに追い詰めます。
- 盤面は駅と路線(タクシー・バス・地下鉄・船)からなる1つのグラフで、背景に川・公園などの簡易地図を描いています。
- 人間の席とBotの席を自由に組み合わせられます。

## 起動方法

```sh
cd chase-game
npm install
npm run dev      # 開発サーバーを起動
npm test         # テスト(Vitest)を実行
npm run build    # 型チェックのあと、公開用の静的ファイルを play/ に出力
```

## 公開(GitHub Pages)

- 公開用にビルドした結果を `play/` にコミットしてあります。リポジトリを GitHub Pages で公開している場合、
  `https://<ユーザー名>.github.io/chase-game/play/` で遊べます(サーバーは不要、静的ファイルだけです)。
- **ソースを変更したら、`npm run build` をやり直して `play/` もコミットしてください。** `play/` はビルド結果なので、直接編集しません。
- `play/index.html` をファイルとして直接開く(`file://`)と、ブラウザの制限で動かないことがあります。サーバー経由で開いてください。

## 遊び方

1. **トップ画面で席を設定します。** 「＋人間を追加」「＋Botを追加」で席を増やし、「削除」で減らします。各席には名前、人間かBotか、逃走者か追跡者かを設定します。Botには難易度(かんたん・ふつう)もあります。プリセット(人間2、人間2+Bot1、人間2+Bot2、人間1+Bot3)から選ぶこともできます。
2. **席の条件:** 席は2〜8席です。逃走者はちょうど1席、追跡者は1席以上、人間は最低1人必要です。条件を満たさないと「ゲーム開始」は押せません。
3. **ゲーム開始後、手番が人間に替わるたびに中継画面が出ます。** 「端末を○○さんに渡してください」と表示されます。本人がボタンを押すまで盤面は見えません。
4. **移動:** 自分の手番では、移動できる駅が光ります。光っている駅をタップし、移動手段(タクシー・バス・地下鉄)を選ぶと移動します。
5. **推理ヒント(追跡者のみ):** 画面上部のボタンでONにすると、逃走者がいる可能性のある駅がオレンジ色で表示されます。
6. 終了後の結果画面で、逃走者の通った道(点線)とログを確認できます。「同じ設定でもう一度」で再戦できます。

## ルール

### 勝敗

- **追跡者の勝ち:** 追跡者のだれかが、逃走者と同じ駅に止まったとき。また、逃走者が動ける手(駅・チケット)を失ったとき。
- **逃走者の勝ち:** 逃走者の移動記録(24手)を埋めて、追跡者が動き終えたとき。また、追跡者が全員動けなくなったとき(チケット切れ、または行き場なし)。

### 手番

- 1ラウンドごとに「逃走者 → 追跡者1 → 追跡者2 …」の順に1回ずつ動きます。
- 動ける手がない追跡者は、自動でパスします。
- 記録は「手数」(逃走者が動いた回数)で数えます。2×カードを使うと、1ラウンドで2手数進みます。

### 移動手段とチケット

| 手段 | 表示 | 使える場所 | 逃走者(最初) | 追跡者(1人あたり) |
|---|---|---|---|---|
| taxi | タクシー(黄色の線) | 全駅 | 6枚 | 12枚 |
| bus | バス(緑の線) | 駅の下に緑の■がある駅 | 4枚 | 8枚 |
| metro | 地下鉄(赤の線) | 駅の下に赤の■がある駅 | 3枚 | 4枚 |

- 手段を使うとチケットが1枚減ります。残りが0枚の手段は使えません。
- 移動先は、いまの駅から線でつながった隣の駅です。
- 追跡者がいる駅には、逃走者も他の追跡者も入れません。追跡者同士も同じ駅には入れません。
- **追跡者が使い終えたチケットは、逃走者に渡ります**(原作のルール)。
- 数値は `src/game/config.ts` にまとめてあります。

### 逃走者だけの特別なカード(スコットランドヤードの要素)

| カード | 効果 | 枚数 |
|---|---|---|
| ブラックチケット | どの路線にも使える。追跡者には「黒」とだけ見え、手段が分からない。**船**(川を渡る黒い点線)に乗れるのはこのチケットだけ | 追跡者2人以下: 1枚 / 3人以上: 人数分 |
| 2×カード | 1ラウンドに続けて2回動ける。それぞれ別のチケットを使い、記録は2手分つく(ブラックとの併用も可) | 追跡者2人以下: 1枚 / 3人以上: 2枚 |

- 残りのブラック・2×の枚数は、逃走者本人の画面にしか出ません。
- 2×は、記録欄に2手分の空きがあるときだけ使えます。2手目を指せなくなる使い方をすると、動けず負けになります。

### 位置の公開

- **3・8・13・18・24手目**に逃走者が動くと、移動後の位置が公開されます(紫のひし形)。2×カードの手も1手と数えます。
- 公開されるのは位置だけです。それ以外の手は、使った移動手段(ブラックなら「黒」)だけが追跡者に見えます。
- 逃走者は、最初★印の5駅のどれかから始まります。

### 見えるもの

- 追跡者の位置とチケット残りは全員に公開されています。
- 逃走者の位置・チケット・ブラックと2×の残りは、本人の手番のときだけ本人に見えます。

## Botの考え方

### 逃走者Bot

- 追跡者への最短距離(BFS、手段は問わず船は含めない)を重く見て、遠い駅を選びます。
- 追跡者が、その駅へ使えるチケットを持って隣接している駅は、大きく減点して避けます(捕まる駅を避けます)。
- 位置公開の直後は、公開された位置から離れる方向を優先します。
- **ブラック:** 貴重なので温存し、追跡者が近いとき・公開直後に使います。
- **2×:** 追跡者が近いときに、2手連続で動くほうが明らかに安全なら使います。
- 「かんたん」では、安全な手の中からランダムに選ぶ確率が上がり、評価にもランダム性が加わります。

### 追跡者Bot

- 公開情報だけ(`publicState`)を使います。公開された位置(なければ★の開始候補)から、使われた移動手段をたどって、逃走者がいる可能性のある駅の集合を計算します。ブラックなら手段を問わず(船も)広げ、追跡者が止まった駅は除きます。
- 評価は「候補の各駅への、追跡者全員のうち最も近い人の距離」の平均です。これが小さくなるように動くので、複数の追跡者が自然にばらけて網を張ります。
- 次の3つの工夫で、無駄な動きを減らしています(詳しくは下の「追跡者Botの改善」)。
  1. **自分自身も候補に近づく** … 他の追跡者のほうが近いときに、手が同点になってランダムに動くのを防ぎます。
  2. **直前の駅へ戻る手を減点** … 往復を抑えます。
  3. **動けなくなる駅を避ける** … 使えるチケットで次に出られない駅(隅など)へは行きません。
- 「かんたん」では、ランダムに手を選ぶ確率と評価のランダム性が増えます。

### 手番の間

- Botの手番は約0.8秒の間を置いてから指します。

## 追跡者Botの改善

対戦ログを見て、追跡者が同じ場所を往復したり、隅でチケットが尽きてパスし続けたりしていたため、原因を調べて直しました。

- **原因:** 評価が「候補の駅までの、全員のうち最短の距離」だけだったので、他の追跡者のほうが近いと、自分がどこへ動いても点が変わらず(同点)、ランダムに動いていました。実測で、判断の約5割が同点のコイントスでした。往復で券を無駄にし、動くたびに使ったチケットが逃走者に渡るため、逃走者を助けていました。
- **効果(Bot同士・各100戦・追跡者タクシー12枚):**

| 追跡者の人数 | 逃走者勝率(改善前→後) | 判断が恣意的な割合 | 直前の駅への往復 | パス回数/試合 |
|---|---|---|---|---|
| 1人 | 65% → 33% | 23% → 16% | 14% → 7% | 0.0 → 0.0 |
| 2人 | 89% → 53% | 41% → 12% | 17% → 9% | 4.2 → 1.5 |
| 3人 | 71% → 38% | 47% → 12% | 21% → 5% | 7.2 → 2.8 |
| 4人 | 55% → 19% | 53% → 14% | 22% → 5% | 8.7 → 2.9 |
| 5人 | 46% → 8% | 57% → 14% | 24% → 4% | 10.3 → 1.2 |

- 「恣意的な割合」は、同じ局面で乱数を変えて6回選び直したとき、選ぶ手が割れた割合です。
- 試したが採用しなかった案: 「逃走者の次の一手を見込んで評価する」。効果が小さく、1人追跡では結果が悪化したため外しました。
- 回帰テストは `tests/bot.test.ts` の「追跡者Botの質」です(原因の再現を含みます)。

## バランス調整について

Bot同士(ふつう同士)を何百戦も対戦させて、勝率と「何で終わったか」を見て枚数を決めています(`src/game/config.ts` の説明も参照)。

- **原作どおりタクシー10枚だと、追跡者2人のとき約半数の対戦が「追跡者が全員動けない」で終わります。** この盤面は50駅のうち34駅がタクシー専用だからです。追跡者Botの改善後は無駄な動きが減ったので、12枚で約1割に収まります。
- 現在の設定での逃走者勝率(Bot同士の目安、上の表): 追跡者2人で約5割、3人で約4割、4人で約2割、5人で約1割。**追跡者が多いほど、逃走者Botは厳しくなります。** 1人は券切れで終わる対戦が約2割あります。
- 逃走者側の強さは、人間とBotで違うはずです。偏りが気になる場合は `config.ts` の枚数(ブラック・2×・タクシー)を調整してください。

## 隠し情報の守り方

- 描画には、必ず `publicState()` を通した状態だけを渡します。`publicState()` は逃走者の位置、チケット(ブラック含む)、2×カードの残り、軌跡を消します。
- 追跡者Botも `publicState()` の結果だけを参照します。逃走者の本当の位置は見ません。
- デバッグ表示(逃走者の位置を画面とコンソールに出す)は、トップ画面の設定で既定オフです。遊ぶときはオフのままにしてください。

## ファイル構成(どこを読めば何が分かるか)

```
index.html               ページ本体(中身は main.ts が組み立てる)
src/main.ts              起動(ui/app.ts を呼ぶだけ)
src/style.css            見た目(スマホ縦画面優先)

src/game/                ← ゲームのルールとBot。画面(DOM)には一切触れない純粋な関数
  types.ts               データの形(盤面・状態・手)。最初にここを読むと全体が分かる
  config.ts              ルールの数値(手数・公開手数・チケット枚数・ブラック/2×の枚数・席数)
  board.ts               盤面データ(駅50個・路線・開始位置)
  rules.ts               合法手(ブラック・船含む)・2×・手の適用・勝敗判定・publicState(隠し情報を消す)
  bot.ts                 Botの思考(逃走者Bot・追跡者Bot・距離計算・可能性のある駅)
  rng.ts                 シード付き乱数

src/ui/                  ← 画面。ゲームの状態を読んでHTMLを作る
  app.ts                 進行制御(次に何の画面を出すか、Botの手番、クリック処理)
  state.ts               画面の状態(どの画面か・設定中の席・進行中のゲーム)
  format.ts              名前・チケット表示などの小さな部品
  rulesText.ts           「ルール」ボタンの説明文
  boardView.ts           盤面のSVGを作る(駒・路線・駅・ヒント)
  boardBackground.ts     盤面の背景の簡易地図(川・公園など)
  screens/
    setupScreen.ts       トップ画面(席の設定)
    handoffScreen.ts     端末受け渡しの中継画面(盤面を出さない)
    playScreen.ts        対戦中の画面
    resultScreen.ts      結果画面

tests/                   Vitestの単体テスト
  rules.test.ts          ルール・勝敗判定
  bot.test.ts            Botの挙動(合法手・捕まる駅を避ける・位置に依存しない)
  special.test.ts        ブラック・船・2×カード・チケット受け渡し・手数による終局
  hidden.test.ts         隠し情報が描画に出ないこと
  board.test.ts          盤面データの整合性(連結・重複なし など)
  setup.test.ts          席の検証・乱数
```

### 変更したいとき
- **チケット枚数・ラウンド数・公開ラウンドを変える** → `src/game/config.ts`(画面のルール文 `ui/rulesText.ts` とこのREADMEの数字も直す)
- **Botを強く/弱くする** → `src/game/bot.ts` の `fugitiveMove` / `chaserMove` の点数づけ
- **盤面を変える** → `src/game/board.ts`(`npm test` で整合性を確認)
- **見た目を変える** → `src/style.css`、盤面の絵は `src/ui/boardView.ts` と `boardBackground.ts`
